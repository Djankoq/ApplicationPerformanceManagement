# Проверка сценариев JMeter

Проверено 14 ноября 2026 года: Apache JMeter 5.6.3, Java 21.0.1,
локальное Spring Boot приложение на `127.0.0.1:18081`, профиль `default`.
ZIP JMeter загружен с зеркала Apache, SHA-512 сверен с опубликованным Apache.
Приложение для проверки запускалось отдельно и остановлено после прогона.

## Основной прогон

Команда: `powershell -ExecutionPolicy Bypass -File scripts/run-jmeter.ps1 -Port 18081`.

| Показатель | Результат |
| --- | --- |
| Пользователи / ramp-up / циклы | 10 / 20 секунд / 10 |
| GET /work/platform | 100 запросов, 0 ошибок |
| GET /work/virtual | 100 запросов, 0 ошибок |
| HTTP и JSON assertions | Все прошли |
| Максимум одновременно активных пользователей в JTL | 10 |
| Разница времени первых запросов первого и последнего пользователей | 17,583 с |
| Разных значений delayMs для каждого сценария | 20 |
| Интервал от начала первого до завершения последнего запроса | 50,035 с |

Исходные результаты: [results.jtl](jmeter/20261114-120850-254/results.jtl),
[HTML-отчёт](jmeter/20261114-120850-254/html/index.html).
Разница времени первых запросов включает случайную паузу перед запросом;
по журналу JMeter потоки запускались с интервалом примерно 2 секунды.

## Короткий и отрицательный прогоны

Короткий прогон с параметрами из README (`-Threads 3 -RampUpSeconds 3 -Loops 3
-ThinkTimeMs 100 -ThinkTimeRangeMs 200`) выполнил 18 запросов без ошибок,
подтвердил 3 одновременно активных пользователя и сформировал HTML-отчёт.
Результаты: [results.jtl](jmeter/20261114-121205-378/results.jtl).

Отдельный локальный тестовый HTTP-сервер возвращал четыре намеренно неверных
ответа: HTTP 503, неправильный `delayMs`, неправильный `virtual`, отсутствующий
`thread`. Все 4 запроса отмечены в JTL как `success=false`; скрипт запуска
вернул ненулевой код. Это подтверждает, что проверки обнаруживают ошибки
статуса и содержимого при HTTP 200. Результаты этого отдельного теста:
[results.jtl](jmeter/20261114-121240-340/results.jtl).

Каталоги исходных JTL/HTML находятся локально и исключены из Git;
новый запуск создаёт новый каталог. Это проверка работоспособности сценариев
с паузами пользователей, а не измерение предельной пропускной способности API.
